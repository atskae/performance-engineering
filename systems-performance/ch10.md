# Chapter 10: Network
Network analysis includes:
* Hardware: phyiscal network: network interface cards, switches, routers, gateways
* Software: kernel network stack: network device drivers, packet queues, packet schedulers, implementation of network protocols
    * Low level protocols are at the kernel level: IP, TCP, UDP
    * Higher-level protocols: HTTP

The network is often blamed since it can get congested and it is easier to blame something complex ("blame the unknown")

## 10.1 Terminology
* **Interface**: *interface port* refers to the phyiscal network connector
    * *Interface* or *link* refers to the logical instance of the network interface port (configured by the OS)
    * Not all links are backed by hardware, some are virtual
* **Packet**: a message in a packet-switched network (ex. IP packets)
    * **Packet-switched network**: breaks down data files into smaller pieces called *packets* (packet swwitching) and independently sends these packets
* **Frame**P: a physical network-level message (ex. Ethernet frame)
    * A frame encapsulates a network packet ("a frame is an envelope, the packet is the letter")
* **Socket**: a networking endpoint (API/interface) that allows two computers to send data to each other across a computer network
    * Stream sockets, TCP: reliable connection, does not lose packets (ex. web-browsing, email, banking transactions)
    * Datagram sockets, UDP: fast but does not guarentee delivery of all packets (ex. video streaming), "fire and forget"
* **Bandwidth**: maximum rate of data transfer of a network, expressed in bits per second
    * "100 GbE" = Ethernet with a bandwidth of 100 Gbits/sec
    * Possible to have bandwidth limits for each direction (inbound and outbound traffic)
        * Ex. A 100 GbE can allow 100 Gbits/sec transmit and 100 Gbits/sec receive in parallel (total throughput: 200 Gbits/sec)
* **Latency**: network *latency* can mean total round-trip time for a message between endpoints, or the time it takes to make a connection (TCP handshake)

## 10.2 Models

### Network Interface
A **network interface** is an OS endpoint for network connections
* System admins configure/administer this abstraction
* The interface is connected to a physical port, which connect to the network
    * Typically have separate transmit and receive channels

### Controller
The **network interface card** contains network ports and a **network controller**: a microprocessor that transfers packets between the ports and the system I/O transport
* The controller can be an extension or built into the system

### Protocol Stack
Networking is accomplished by a stack of protocols, each with a particular purpose

Example of the TCP/IP stack:
| TCP/IP | Example Implementations |
| - | - |
| Application | HTTP, DNS |
| Transport | TCP, UDP |
| Internet | IPv4, IPv6 |
| Data Link | Ethernet |
| Physical | copper, fiber |

Sent messages move down the stack from Application to the Physical layers. Received messages move up the stack from Physical to the Application layer.

Additional layers can be used for added security (ex. IPsec, Linux Wireguard)

Another example network protocol stack is the OSI model, which has more layers defined within the Application layer.

Each layer also uses different terminology for a message
* Ex. in the OSI model, in the network layer a message is called a *packet*, in the data link layer it is called a *frame*


### 10.3 Concepts

#### Networks and Routing
A **network** is a group of connected computer nodes
* Related by *network protocol addresses* (also called internet protocol, or IP address)
* Having multiple networks (instead of one giant network) scales better when *broadcasting* messages

**Routing** manages the delivery of messages, called *packets*, across the network
```
[ Host A, B] ---> [Router 1] ---> [ Host C ] ---> [Router 2] ---> [ Host D, E] 
```

In the perspective of Host A, Host A itself is the *localhost*, and the other hosts are *remote hosts*.
* Host A can connect to Host C via Router 1 and connect to Host D via Routers 1 and 2, all through the local network
* Routers are shared across the local network, so contention is possible

A connection between two hosts is called a *unicast* transmission
* *Multicast* transmission is when a host sends a message to multiple other hosts (which could be outside the local network)
    * The router needs to support multicasting

*Firewalls* can also be used to improve security by blocking unwanted connections

The **IP header** in the packet tells the router to which host/router to send the packet to

#### Protocols
A **network protocol standard** are widely accepted rules, data formats and procedures that allow different systems and devices to communicate with each other across a network
* Examples in different network layers:
    * Network layer: IP (IPv4, IPv6) - packet addressing and routing
    * Transport layer: TCP, UDP - reliable delivery vs. fast streaming
* Communication is done by transferring routable messages called *packets*

Different network protocols can have different performance implications and handled by different software/kernel code
* Ex. IPv4 vs IPv6

Different protocols for different use-cases/workloads
* Ex. Stream Control Transmission Protocol (SCTP): Transport layer network protocol, reliable like TCP but for streaming like UDP
* Ex. Multipath TCP (MPTCP) - a Transport layer extension that allows a single connection to send data across multiple network paths simultaneously
* Ex. QUIC "kwik" - Transport layer protocol developed at Google by Jim Roskind, built on top of UDP and speeds up web connections and reduces latency

Each protocol can be tuned, which affects performance
* Ex. buffer sizes, algorithms, timers

Data is transported across the network via *encapsulation*.

#### Encapsulation
**Encapsulation** adds a metadata to the payload at the start (the *header*) or to the end (the *footer*), or both.
* The payload size does not change, but the total message size changes

Example of TCP/IP with Ethernet:
| | | | | |
|-|-|-|-|-|
| | | | Payload | |
| | | TCP | Payload | |
| |IP| TCP | Payload| |
|E.H.|IP|TCP|Payload|E.F.|

with Transmit from top row to bottom row, and Receive from bottom row to top row.
* `E.H.` is the Ethernet header and `E.F.` is an optional Ethernet footer

#### Packet Size
Packet size impacts performance
* Larger sizes improving throughput and reducing packet overheads
* TCP/IP, packet sizes range from 54 - 9,054 bytes, including the ~54 bytes of protocol headers (size depends on the protocol)

Packet size is limited by the network interface's **maximum transmission unit** (MTU) size
* Ethernet MTU size is ~1,500 bytes
